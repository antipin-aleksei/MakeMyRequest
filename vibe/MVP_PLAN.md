# План до первого тестового MVP

Статус: план, 17.11.2026  
Продукт: персональная страница конкретного тату-мастера для сбора подробных запросов и заявок на сеанс. Не маркетплейс и не платформа студий.

## 1. Закрепить архитектуру и инструменты
- [ ] Перейти с Mantine на **shadcn/ui + Tailwind CSS**, убрать Mantine-зависимости.
- [ ] Обновить `AGENTS.md`, frontend skill и ADR о UI kit: строгие границы Rust API / React / PostgreSQL, понятные правила разработки.
- [ ] Проверить локальную сборку, миграции БД, тесты и зелёный GitHub Actions.

## 2. Сделать понятную мобильную страницу мастера
- [ ] Профиль мастера, краткое описание, условия и две основные кнопки: **«Обсудить идею»** и **«Запросить сеанс»**.
- [ ] Адаптивный интерфейс для телефона, WebView и компьютера на готовых компонентах shadcn/ui.
- [ ] Состояния загрузки, ошибок и успешной отправки.

## 3. Реализовать полноценную анкету клиента
- [ ] Собирать контакты, описание идеи, стиль, место нанесения, размер, бюджет и пожелания.
- [ ] Добавить загрузку фотографий и референсов в приватное файловое хранилище.
- [ ] Для заявки на сеанс — желаемая дата/время **без обещания свободного слота или подтверждения**.
- [ ] Заложить версионирование анкеты, чтобы позднее мастер мог менять вопросы.

## 4. Сделать рабочий кабинет мастера
- [ ] Закрытый вход для мастера.
- [ ] Список заявок, карточка с ответами и референсами, фильтры по статусу.
- [ ] Смена статуса заявки и возможность отметить, что требуется уточнение или заявка принята.
- [ ] Без внутреннего чата на первой итерации: для ответа достаточно контактов клиента.

## 5. Подготовить безопасный backend и данные
- [ ] Rust/Axum API для заявок, мастера и кабинета; PostgreSQL + SQLx + миграции.
- [ ] Серверная валидация, ограничения размера вложений, защита от спама и ограничение частоты запросов.
- [ ] Контроль доступа к заявкам и изображениям; согласие на обработку данных и базовая политика конфиденциальности.
- [ ] Проверки ключевых пользовательских сценариев и сохранности данных.

## 6. Развернуть тестовую среду
- [ ] Подключить бесплатные или условно-бесплатные облачные сервисы для frontend, Rust API, PostgreSQL и файлов.
- [ ] Настроить переменные окружения, HTTPS, CI/CD и изоляцию тестовой БД.
- [ ] Проверить работу по публичному URL с мобильного телефона и компьютера.
- [ ] Подготовить безопасные тестовые данные; не использовать реальные фото/контакты без необходимых условий обработки.

## 7. Провести приемочное тестирование MVP
- [ ] Клиент открывает страницу мастера → заполняет заявку → прикладывает референсы → отправляет.
- [ ] Заявка и файлы сохраняются, клиент получает подтверждение **получения запроса**.
- [ ] Мастер входит в кабинет → видит новую заявку → открывает вложения → меняет статус.
- [ ] Проверены ошибки, мобильные экраны, доступы и повторная отправка.

## Вне первого MVP
- AI/LLM и анализ изображений.
- Конструктор анкет в кабинете (пока фиксированная схема с версиями).
- Автоматическое бронирование подтверждённых слотов, оплаты и депозиты.
- Встроенная переписка, пуш-уведомления, интеграции Telegram/календарей.
- Поддержка студий и нескольких мастеров.

## Критерий готовности
Первый тестовый MVP готов, когда **по доступному HTTPS-адресу клиент может отправить содержательную заявку с референсами, а мастер — безопасно открыть и обработать её в своём кабинете**. Сеанс считается только запросом до ручного подтверждения мастером.
