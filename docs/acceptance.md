# MVP: приёмочные сценарии

Все тесты только на синтетических данных. Статус: написаны, **не пройдены**.

1. **Публичная страница:** на 320px/WebView/Desktop загружается имя и bio мастера; доступны два вида заявки. При сбое API видна ошибка, кнопки блокируются.
2. **Анкета:** обязательные поля и согласие проверяются, 1–3 референса JPG/PNG/WebP размером <= 5 MB прикрепляются. Опечатки/ошибки сети обрабатываются.
3. **Запрос на сеанс:** выбранная дата сохраняется как предпочтение, а не как подтвержденная запись.
4. **Постоянство данных:** `POST /api/v1/requests` возвращает id и временный upload token. После upload metadata и файлы доступны по id заявки только мастеру.
5. **Контроль доступа:** /api/v1/admin/requests, /api/v1/admin/requests/:id, /api/v1/admin/attachments/:id возвращают 401 без ключа. С правильным ключом мастер видит личные данные и приватные изображения.
6. **Обработка заявки:** мастер устанавливает `in_review`, `needs_info`, `accepted` или `declined`. Статус сохраняется после обновления экрана.
7. **Ошибки/абьюз:** неподходящий файл отвергается, четвертый файл блокируется, токен чужой заявки отвергается; отсутствие API и БД показывается корректно.
8. **Развертывание:** проверить тестовый HTTPS-адрес, заголовки CORS, загрузку в приватный R2, логи без PII и базовое восстановление данных.
9. **CI:** зафиксировать результат `typecheck`, `build`, `cargo fmt`, `clippy`, `cargo test` и миграции с PostgreSQL.

Без полного выполнения критических пунктов публичный запуск не разрешён.
